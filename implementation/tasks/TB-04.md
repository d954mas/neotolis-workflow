# TB-04 — Locking and atomic state storage

## Goal

Implement the single project-local transaction mechanism used by all state-changing operations.

## Dependencies

- `TB-03` committed and passing.

## Owned files

- `src/runtime/transaction.ts`
- `tests/transaction/**`
- transaction-specific fixtures and fault injectors

Do not add run or phase commands.

## Implementation contract

- Acquire `.ntworkflow/.state.lock` with exclusive create.
- Store process ID and a random token; release only a lock whose token still matches.
- Existing locks fail immediately, without retry, TTL, stale detection, or repair.
- Serialize state as UTF-8, LF, canonical two-space JSON.
- Write a sibling temporary file, sync it, close it, and rename it over `state.json`.
- Sync the parent directory on Unix where supported; keep Windows handles closed before rename.
- Expose deterministic fault points before write, after temp sync, and before rename.
- Failed replacement leaves previous `state.json` byte-for-byte intact.
- Keep transition calculation pure and inside the acquired lock/read/validate/write boundary.

## Acceptance

`TB-AC-04` is complete when concurrent mutations serialize and every injected commit failure preserves the previous state.

## Verification

```powershell
npm run check
node scripts/run-tests.mjs transaction
```

Expected:

- exactly one of two racing mutators commits;
- the other returns lock conflict/exit `15`;
- all injected failures preserve previous bytes;
- a foreign lock token is never deleted;
- all lock/temp files stay under `.ntworkflow/`.

Report commit, transaction API, lock lifecycle, fault hooks, verification, deviations, and blockers. Stop.
