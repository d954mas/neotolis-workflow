# TB-01 — Tooling and CLI JSON protocol

## Goal

Create the reproducible Node.js 24 package foundation and stable machine protocol used by every later packet.

## Dependencies

None.

## Owned files

- `package.json`, `package-lock.json`, `.nvmrc`
- `tsconfig.json`, `eslint.config.js`
- `scripts/build.mjs`, initial `scripts/run-tests.mjs`
- `src/core/protocol.ts`, `src/core/errors.ts`
- `tests/tooling/**`

Do not create CLI command handlers, state types, plugins, or future-operation placeholders.

## Implementation contract

- ESM TypeScript package named `@neotolis/workflow`.
- `engines.node` is `^24.0.0`; `.nvmrc` contains `24`.
- No production dependencies.
- Lock exact development versions needed by the approved plan, including TypeScript/build/lint tooling, Claude Code `2.1.220`, and Codex `0.144.6`.
- Define typed success/failure responses and a serializer that emits exactly one JSON line.
- Define the stable exit-code mapping from `implementation/PLAN.md`.
- Caught errors must not expose stack traces in protocol output.

## Acceptance

`TB-AC-01` is complete when tooling is reproducible and protocol tests lock the JSON and exit-code contract.

## Verification

```powershell
npm ci
npm run check
node scripts/run-tests.mjs tooling
npm run build
```

Expected:

- all commands exit `0`;
- a second `npm ci` produces no lockfile diff;
- protocol tests prove one-line JSON output and stable codes;
- build output contains no future commands or plugins.
