# TB-02 — Strict state model

## Goal

Implement exact parsing and invariant validation for the complete `state.json` shape in `RUNTIME.md`.

## Dependencies

- `TB-01` committed and passing.

## Owned files

- `src/core/state.ts`
- `src/core/invariants.ts`
- `tests/state/**`
- `tests/fixtures/states/**`

Do not add filesystem access or transitions.

## Implementation contract

- Define `State`, `Current`, `Work`, `Task`, evidence, verdict, owner, and pull-request types exactly as confirmed.
- Use small local exact-object/type guards, not a generic schema framework.
- Reject missing, unknown, and wrongly typed fields.
- Enforce lifecycle/phase/owner/work/task/verdict cross-field invariants.
- Validate canonical session IDs and run/task ID syntax.
- Run IDs accept at least three digits; task suffixes accept at least two digits.
- Validation is pure and does not mutate the input object.
- Legal future states are readable even though their commands are not implemented in this slice.

## Acceptance

`TB-AC-02` is complete when every legal state fixture parses and focused invalid mutations fail with stable state error details.

## Verification

```powershell
npm run check
node scripts/run-tests.mjs state
```

Expected:

- every confirmed lifecycle has legal fixtures;
- single-field unknown/missing/type mutations fail;
- invalid phase/lifecycle, work/task, owner, and verdict combinations fail;
- fixtures and input values remain unchanged.

## Handoff

Report commit, exported state/parser APIs, invariant error shape, verification, deviations, and blockers. Stop.
