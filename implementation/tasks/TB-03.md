# TB-03 — Project root, read-only preflight, and status

## Goal

Deliver the first runnable `ntworkflow` command with canonical project-root discovery and non-mutating status inspection.

## Dependencies

- `TB-02` committed and passing.

## Owned files

- `src/runtime/project-root.ts`
- `src/runtime/preflight.ts`
- `src/cli/arguments.ts`
- `src/cli/main.ts`
- `tests/status/**`
- `tests/fixtures/consumer-repos/**`

## Implementation contract

- Canonicalize the provided `--cwd` and require an accessible directory.
- Walk upward to the nearest `.git` directory or worktree `.git` file.
- Outside Git, use the canonical supplied cwd.
- Read an absent or present `.ntworkflow/state.json` through `TB-02`.
- Implement only `status`; all other commands are unknown at this point.
- `status` returns actual state and a correct next action.
- An uninitialized project returns `state:null` and next skill `nttask`.
- Never create `.ntworkflow/` or any other file.

## Acceptance

`TB-AC-03` is complete when status is runnable from nested Git, worktree, and no-Git fixtures without mutation.

## Verification

```powershell
npm run check
npm run build
node scripts/run-tests.mjs status
node build/cli/ntworkflow.mjs --cwd tests/fixtures/consumer-repos/empty status
```

Expected:

- nested and worktree fixtures resolve the correct root;
- no-Git resolves the passed cwd;
- the final command emits `ok:true`, `state:null`, `next_action.skill:"nttask"`;
- all fixture trees remain byte-for-byte unchanged.
