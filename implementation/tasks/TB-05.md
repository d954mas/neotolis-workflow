# TB-05 — Run lifecycle and ID allocation

## Goal

Implement run creation, cancellation, and completion independently of phase-specific reasoning.

## Dependencies

- `TB-04` committed and passing.

## Owned files

- `src/runtime/run.ts`
- run-related integration in `src/cli/main.ts`
- `tests/run/**`

## Implementation contract

- Add `run start`, `run cancel`, and `run complete` only.
- Allocate stable project-local IDs starting with `NT-001`; never reuse an allocated number.
- Use minimum three-digit padding and allow `NT-1000` after `NT-999`.
- Prepare the permanent run directory before committing state.
- A first run enters `intake-active` with `phase`, `owner`, `blocker`, and `work` all `null`.
- Starting from `delivery-ready` prepares the new run and selects it in one state commit.
- Cancellation is legal from confirmed active lifecycles, requires explicit user authority, clears `current`, and preserves the run directory.
- Completion is legal only from `delivery-ready`, requires explicit user authority, and clears `current`.
- A pre-existing target run directory is `PARTIAL_RUN`; never delete or adopt it.

## Acceptance

`TB-AC-05` is complete when allocation and every legal/illegal run boundary are covered without ID reuse or automatic repair.

## Verification

```powershell
npm run check
npm run build
node scripts/run-tests.mjs run
```

Required scenarios:

- `first-run-is-NT-001`
- `canceled-id-is-not-reused`
- `NT-999-advances-to-NT-1000`
- `cancel-preserves-run-directory`
- `complete-clears-current`
- `delivery-ready-start-is-one-state-commit`
- `commit-failure-leaves-old-current-and-partial-directory`
