# TB-10 — Provider conformance and packaging

## Goal

Prove provider semantic parity and assemble complete locally installable release artifacts.

## Dependencies

- `TB-08` committed and passing.
- `TB-09` committed and passing.

## Owned files

- `tests/conformance/**`
- shared provider scenario corpus
- `scripts/package-plugins.mjs`
- package/marketplace inventory tests
- final test/package aliases in `package.json` and resulting lockfile updates if required

Do not change provider skill semantics unless conformance exposes a concrete defect; route such a defect back to its owning task instead of silently redesigning it here.

## Implementation contract

- Drive one JSON scenario corpus through both recorded provider adapters.
- Normalize only provider/session IDs and absolute fixture paths.
- Compare operation, exit class, lifecycle, next action, warnings, and filesystem hashes.
- Build an npm tarball plus complete Claude and Codex local marketplace trees.
- Both plugins must contain byte-identical runtime bundles.
- Verify inventories exclude future skills/agents, tests, source-only files, telemetry, and credentials.
- Verify the npm tarball exposes the `ntworkflow` bin.

## Acceptance

`TB-AC-10` is complete when provider results are semantically equivalent and every packaged artifact is self-contained and locally installable.

## Verification

```powershell
npm run check
npm run build
npm run test:conformance
npm run package
npm run package:verify
```

Expected:

- all normalized scenarios match;
- runtime bundle hashes match;
- the npm tarball installs and exposes `ntworkflow`;
- both marketplace fixtures install locally;
- artifact inventories contain only approved files.

## Handoff

Report commit, artifact paths and hashes, conformance summary, verification, deviations, and blockers. Stop.
